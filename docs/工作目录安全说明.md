# 工作目录安全说明

## 本次修复

- 进入存档探测而需要管理员重启时，保留便携模式和显式工作目录参数，不再意外改读另一份配置。参数按独立元素传递，支持中文、空格、尾部反斜杠；交互式提权不继承开机自启的静默隐藏标志。
- PowerShell 备用文件/目录选择器明确按 UTF-8 接收输出，避免父子进程编码不一致。
- 「复制并切换」代替原来的搬迁清理：只复制已登记游戏的子目录，逐文件 SHA-256 校验，绝不自动删除旧目录或覆盖已有目标游戏数据。与游戏无关的资料不复制、不删除；临时快照不迁移。
- 拒绝相同、父子重叠、符号链接/目录联接和设备路径；目标不能直接是磁盘根、已知文档/桌面等用户或系统目录，请创建专用备份子目录。
- 页面和服务均拒绝重复切换；游戏运行、停止中或定时备份开启时不能切换。复制期间新的存档目录请求被拒绝；提交前再次核对游戏清单、源文件清单和内容，发现变化则取消切换。
- 配置采用同目录临时文件写完后替换，串行保存；切换保存失败时恢复内存中的旧工作目录。显式 `--workdir` 只影响运行时，不会随其他设置保存到配置中。

## 使用方法

1. 退出游戏，停止定时备份，等待所有备份和同步结束。
2. 在设置中选择一个独立的专用文件夹。
3. 「复制并切换」复制已有游戏数据；「仅切换」不复制数据。两种方式均保留旧目录。
4. 复制完成后，确认新目录备份齐全。程序不会自动清理旧副本，旧目录也不是无用缓存。
5. 若复制失败或目标已有游戏数据，旧目录和配置不会因此被删除。新目录可能留有部分副本，请使用另一个空目录；不要未经核对就删除旧副本或异常名称目录。

配置文件位置保持不变：普通模式为用户目录中的 `xingchen\ycyaw\.gamesave\config.json`；便携模式为启动器传入的 `GameSave-Data\config.json`，与当前备份工作目录是不同概念。

## 验证方式与边界

自动化测试只在唯一临时目录中构造服务配置，不调用真实配置初始化，不启动应用、游戏、UAC 或选择器。覆盖中文路径、嵌套图标、无关资料保留、父子重叠、同名冲突、保存失败、复制期间源变更、重复操作和并行配置保存；参数/编码测试仅检查启动信息，不实际创建子进程。

这不是实时同步：本机其他程序或已取得旧文件路径的任务，仍可能在最终校验之后修改旧副本，因此复制期间必须停止游戏、备份和同步。旧副本始终保留。本次不自动合并不同来源的历史配置、不修正历史乱码目录，也不宣称能恢复此前丢失的文件。

## 还原与删除游戏的额外防护

- 手动还原、启动时恢复退出存档，均在删除任何文件之前统一校验所有目标；手动还原也先检查所有目标是否被占用，再开始清空。
- 拒绝把磁盘根、文档、桌面、用户、AppData、程序安装根目录及其上级作为还原目标；允许专用游戏子目录，包括默认 Steam 安装位置下的具体 `userdata` 存档目录。Windows 操作系统目录及其子目录始终拒绝。
- 目标之间不能重复或互相包含，不能与备份工作目录重叠，也不能包含源存档或配置文件。目标及其父链、目录树内的符号链接/目录联接会被拒绝，避免越界清空。
- 删除游戏前验证游戏标识为单段目录名，并拒绝链接工作目录，防止异常导入标识把删除带到备份目录之外。链接/OneDrive 重定向目录可能因此被拒，请核对实际位置，不要绕过提示。
- 正常还原仍会替换所选游戏原始存档，并非完整的事务回滚系统；磁盘或权限故障仍可能中断还原。不要把整个文档目录当作游戏原始存档路径。

路径预检和还原集成测试使用临时树及临时目录联接；实际用户/系统根只进行路径字符串拒绝判定，Steam 子目录兼容性使用纯字符串策略测试，不枚举真实用户内容。历史数据丢失的具体原因仍需要额外证据。
